# 書籍更新與版本驗證規則

本文件規定使用者如何確認某一本書的修正已真正進入線上書庫，以及內容更新不得破壞閱讀進度的邊界。

## 一、兩種版本必須分開

- **書庫版本**：代表整個網站部署包，例如 `2026.07.27-6`。任何一本書或介面更新都可能提高它。
- **書籍版本**：每一本書各自獨立，例如微積分 `2026.07.27-3`、會計學 `2026.07.27-1`。

確認某一本書是否完成修正時，必須看該書自己的書籍版本；只看書庫版本不夠，因為書庫版本可能是其他科目造成的更新。

## 二、線上可見驗證

每本書的書庫卡片與書籍首頁必須顯示：

1. 書籍內容版本。
2. 最後更新日期。
3. 「查看版本與更新內容」區塊。
4. 本版修正摘要。
5. 本次更新對閱讀進度的影響。

沒有以上可見資訊，不得只靠助理口頭表示「已更新」。

## 三、完成回報格式

每次正式修正完成後，必須回報：

- 舊版本 → 新版本。
- 書庫版本。
- 3 個以內的主要修改項目。
- 2 至 3 個可在平板上直接抽查的可見位置。
- QA 檢查數量與結果。
- 閱讀進度影響：`不變`、`重新計算但紀錄保留`，或其他明確說明。
- 固定網址是否不變。

## 四、閱讀進度規則

- 閱讀進度與內容版本分開保存在使用者平板中。
- 閱讀百分比不是版本驗證工具；百分比不變不代表內容沒有更新。
- 一般勘誤、文字改寫、例題或題庫修正，必須保留相同的 `book id`、章節 ID 與章節數，使既有閱讀進度不變。
- 若必須新增、刪除或拆分章節，百分比可能因總章節數改變而重新計算，但已讀章節與最後閱讀位置應盡量保留。
- 未經使用者明確同意，不得清空閱讀進度、錯題紀錄或字體設定。

## 五、發布門檻

發布前必須確認：

- 書籍版本已提高。
- 書庫版本已提高。
- 更新紀錄已寫入該書 manifest。
- service worker 快取版本已提高。
- 既有進度儲存鍵與書籍 ID 未被意外修改。
- QA 報告與 shared checkpoint 已同步。
- 線上部署回執顯示成功。

## 六、使用者實際確認方式

在平板上：

1. 重新開啟「重點複習」。
2. 在書庫卡片查看目標書籍的內容版本。
3. 點入該書，確認內容版本與最後更新日期。
4. 展開「查看版本與更新內容」。
5. 依完成回報提供的抽查位置，任選一至兩處確認。

以上成立，即可確認修正版本已實際載入，而不是只完成了本機檔案或 GitHub 文件。
